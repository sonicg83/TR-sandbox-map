# TRMap 初版设计

状态：讨论稿，待用户审阅。日期：2026-11-13。

## 目标与边界

面向单人本机使用，提供独立的 Travian 地图沙盘。用户将已有工具生成的地图数据导入后，在接近 TravianZ 的地图上观察村庄、联盟、地块和绿洲，标注战场方案。沙盘不会执行游戏内操作。

首版完成的标准是：用户能以已验证的服务器样本导入数据、定位一片区域、理解数据的新旧与缺失、创建并保存本地方案，重启后继续使用。

## 方案选择

已选择本地 Web 应用：本机运行服务并在浏览器操作，数据保存在本机。Python 后端便于衔接现有解析工具；地图由独立前端渲染。相比原生桌面应用，这需要同时维护前后端，但更适合参考现有网页地图，且无需首版解决应用打包问题。

首版通过文件导入，继续由外部 `travian-scan` 执行扫描；不在沙盘中登录、启动扫描或管理扫描任务。每日数据也先手动导入。之后可在保持数据接口稳定的前提下增加按需扫描和自动更新。

## 首版用户流程

1. 创建本地服务器档案，填写名称、世界或赛季标识、坐标范围；边界环绕规则只有经样本验证后才能启用，不能默认适用于所有服务器。
2. 选择目标档案，导入一份 `map.sql` 和一份 `travian-scan` 聚合 JSON。允许分开导入；导入前显示来源、时间和范围等可确认信息，导入后显示成功、跳过、冲突和错误数量。原文件不被修改。
3. 在地图拖动、缩放、跳转坐标，点击地块查看坐标、类型、可用的资源分布、村庄、玩家、联盟、人口，以及各项数据来源与时间。无对应观察的内容显示未知。
4. 搜索坐标、村庄、玩家或联盟；按联盟及地块类型筛选或突出显示。对于空地和绿洲，只有有明确观察时才显示可用或占用。
5. 创建本地沙盘方案，在地图添加、编辑和删除文字标记及带方向的路线，保存颜色和备注；重新打开后保留。方案与服务器观察分开存储。
6. 导入新的每日文件或局部扫描结果，更新相关观察并保留旧批次；用户仍能查看数据时间。首版不要求构建完整历史回放。

## 地图呈现

- 视觉方向尽量接近 TravianZ 游戏地图，包括可辨认的地块排列、村庄、绿洲和地貌；缩放、拖动、坐标与点击必须保持一致。
- TravianZ 的地图模板依赖其数据库、游戏状态和会话，不能假设可直接作为独立组件使用；提取渲染逻辑和素材之前先验证实际依赖及许可。保留必要归属；若某素材不能确认许可或类型无法映射，使用明确区分的占位表现，并记录限制，不伪造精确地貌。
- 先以参考项目样本核验坐标方向、投影、资源分布与素材映射；世界范围和边界规则按服务器配置。按视口渲染，避免因一次加载全部地块造成明显卡顿；具体技术和可测性能指标在样本基准验证后确定。

## 数据与合并规则

- 地块以服务器档案、世界或赛季和 `(x, y)` 标识。持久化分为导入批次、地图基础观察、动态观察、沙盘方案；保留来源和原始记录或足以追溯的导入记录。
- `map.sql` 作为每日村庄观察来源；扫描 JSON 的 `village`、`oasis` 和 `landscape` 提供地块类型、资源分布及部分可用状态。现有扫描聚合格式并未提供完整玩家、联盟和人口，也没有逐地块观察时间或完整失败清单，不能据此推断这些信息。
- 每批次记录数据来源、导入时间、用户确认的观察时间及其精度；导入时间不是观察时间。缺少可信观察时间时明确显示“观察时间未知”，不按文件名或导入时刻伪造。局部或长时间扫描的时间与覆盖范围不确定时按批次说明，不假定所有地块同一时刻被观察。
- 合并按字段与来源处理，而非整条记录覆盖。较新且时间可信的同类观察可更新当前视图；无法比较时间或来源相互矛盾时保留冲突并显示，不静默覆盖。更新失败应避免部分结果被误认为完整批次。
- 一份文件未包含某坐标，不代表该坐标已扫描、为空或扫描失败；仅当输入包含可靠的覆盖和结果信息时才能作相应判断。即便完整的每日文件中不再包含某村庄，也只记录它不在该快照中，不推断原因；完整性未确认时不能推断消失。
- 同一坐标出现在互斥类别、数据格式不支持或服务器身份不匹配时应提示并阻止错误合并。未知字段、资源分布与人口缺失保持未知，不自动转换为零。

## 范围之外

多人协作、账号和远程部署；在沙盘内启动扫描、自动下载或持续实时同步；战斗模拟与游戏操作；从未观察到的数据推断兵力或库存；自动资源调度和行军时间计算；WPS 同步。它们可在后续单独规划。

## 验收

- 用经脱敏的代表性样例验证 SQL 和扫描 JSON 导入、失败提示、批次信息和重复导入；禁止执行导入的 SQL 内容作为数据库命令。
- 同一坐标的村庄与扫描属性可正确关联；局部扫描缺失坐标保持未知；时间未知和新旧冲突有明确展示，旧批次不丢失。
- 地图坐标跳转、拖动、缩放和点击指向同一地块；边界及投影使用已验证的服务器配置；无法识别的素材或类型明确显示。
- 搜索、筛选、标记和路线可用；本地服务重启后数据和方案仍在，方案不会被数据重新导入覆盖。
- 通过参考项目中与样例对应的地块对照，核查视觉映射和必要归属；对无法验证的范围写明限制。仓库测试仅使用人工或已脱敏且许可明确的样例。

## 尚需验证和实施时决定

- 目标服务器样本是否提供足够地块属性以还原对应画面；不同服务器版本的地貌与素材映射是否一致。
- TravianZ 代码及具体素材的权利、许可和分发条件；合法复用范围确认前不将素材复制到本仓库。
- 现有扫描 JSON 的时间、扫描范围和失败信息是否由相应附加文件提供；如不能确认，界面必须保留未知状态。
- 选择具体前端绘图库、后端框架与 SQLite 表结构，并根据真实世界规模制定性能基准；这些是实施阶段的技术选择。
