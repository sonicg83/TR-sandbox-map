# 地图数据导入说明

TRMap 初版通过文件导入数据。请先在界面中创建并选中对应服务器和赛季；程序目前无法从文件中自动验证归属。

## 每日村庄数据

在「地图数据」中选择「每日地图 map.sql」，再选择服务器每日提供的 `map.sql`。导入器读取其中的 `x_world` 插入记录，用于展示村庄、玩家、联盟和人口等信息；它只解析文件，不执行 SQL。

每日文件不包含完整地貌、空地和绿洲信息，建议同时导入扫描结果。

## 扫描结果 JSON

选择 `schema_version` 为 1 的扫描 JSON。文件包含 `metadata` 对象和 `tiles` 数组；旧版按 `village`、`oasis`、`landscape` 分组的格式不再支持。例如：

```json
{
  "schema_version": 1,
  "metadata": {"source": "scanner", "coverage": {"kind": "world"}, "complete": true},
  "tiles": [
    {"x": 1, "y": 2, "kind": "village", "static": {"resources": {"Lumber": 3, "Clay": 4, "Iron": 5, "Crop": 6}}, "observations": [{"source": "position", "observed_at": "2026-01-01T00:00:00Z", "fields": {"occupied": false}}]},
    {"x": 2, "y": 2, "kind": "landscape", "static": {"landscape_type": "Lake"}, "observations": []}
  ]
}
```

`kind` 为 `village`、`oasis` 或 `landscape`；村庄和绿洲通过 `fields.occupied` 区分已占领与未占领。缺失状态保持未知；资源可以为 `null`，不会推断资源。地貌类型保存在 `static.landscape_type`。地块坐标不得重复，且必须在当前服务器范围内。扫描观察保留来源、时间、动物、玩家、联盟等原始字段；文件元数据保存在导入记录中。每条观察优先使用自身的 `observed_at`；缺失时才使用用户填写的观察时间，不使用扫描结束时间代替。多个观察按时间和冲突规则分别处理。

导入上限为 50 MB。文件的服务器归属仍需用户确认，元数据中的覆盖范围和完成状态不会自动证明缺失坐标为空地。

## 时间、更新与限制

1. 选择数据类型和文件；如果能确定观察时间，填写该时间。浏览器会将所选本地时间换算为带时区的时间。
2. 如果扫描持续较长时间或观察时间不确定，请留空。导入时间会单独记录，不会冒充观察时间。
3. 点击「导入数据」并检查结果。选择文件即表示你确认它属于当前服务器；错误文件、重复观察及越界坐标会被拒绝，失败不会写入部分记录。
4. 新文件可再次导入。相同文件如有不同的确认观察时间，可以作为新的观察；同文件、同观察时间的重复导入会被拒绝。

文件没有提及某坐标时，不能说明它为空、已被扫描或扫描失败。不同来源和观察时间的数据分别显示；无法判定新旧的不同观察会提示冲突。当前不会自动执行扫描或下载每日文件，也不会自动认定文件覆盖完整地图。

本地数据保存在 `data/trmap.sqlite3`。备份前先停止服务，再复制该文件。地图使用自绘示意地块，尚未验证 TravianZ 素材与目标服务器的完整映射。


地图左侧的工具栏可在 100%、50%、10% 三档之间缩放，并可回到原点。10% 为快速总览：只显示已知村庄、与村庄相关的观察冲突及方案标记；其他地块不会在总览中标为未知或空地。点击坐标会单独加载该地块的完整观察，放大后可查看地貌和绿洲。人口等级只根据已知村庄人口绘制，不明人口不会推定等级。

50% 和 100% 地图按视野加载绘图所需的地块摘要，点击地块后单独读取完整观察、来源和时间；拖动或缩放不会为每个地块读取详情。
